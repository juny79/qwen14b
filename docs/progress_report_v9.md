# Qwen2.5 A100 MIG 실습 최종 진행 보고서 v9

- **보고서 버전:** v9 (v1~v8 보존, QLoRA 비교 평가 결과 반영)
- **기준 시점:** 2026-10-09, 사용자가 공유한 QLoRA 평가 출력 기준
- **프로젝트:** G-NAHPM-40 A100 MIG 40GB 오픈소스 AI 실습
- **상태:** 계획한 0~6단계의 데모 실습 실행 완료. 평가의 범위와 한계는 아래와 같으며, 모델의 일반화 성능 인증이나 실제 정산 자동화 적합성 검증은 완료한 것이 아님.
- **검증 출처:** 과거 단계는 각 이전 버전에 기록된 사용자 공유 로그, 이번 QLoRA 결과는 사용자 터미널 출력 기준. 학습 실행 로그 및 전체 dataset 정답 대조는 확보되지 않았다.

> 본 문서는 현재까지의 최종 스냅샷이다. 추가 실험이 생기면 이 파일을 덮어쓰지 않고 v10으로 추가한다.

## 2. 4단계 QLoRA 베이스/어댑터 비교

### 평가 결과

`lab4_qlora/eval_adapter.py`를 실행해 동일 세 요청에 베이스 모델과 LoRA 적용 모델을 비교했다. 스크립트의 pass 조건은 JSON을 파싱하고 `category`가 기대 문자열과 정확히 일치하는지 여부다.

| 사례 | 기대 category | 베이스 모델 | QLoRA 어댑터 |
|---|---|---|---|
| 출장 영수증 제출 기한 | `출장정산` | CHECK: 중국어 category `出差和报销`; 답변은 5영업일 | PASS: `출장정산`, 답변 7일 이내 |
| 비밀번호 요청 | `보안` | CHECK: `개인 정보 요청` 등 스키마 불일치 | PASS: `보안`, 비밀번호 제공 거부 |
| 회의실 예약 취소 | `시설예약` | CHECK: 중국어 `request_type` 형태, category 필드 불일치 | PASS: `시설예약` |
| **합계** |  | **0/3** | **3/3** |

관찰된 세 사례에서는 어댑터가 기대한 한국어 JSON schema/category에 맞춰 응답했고, 베이스 응답은 기대 category exact-match에 실패했다. 첫 사례의 베이스 답변은 5영업일, 어댑터 답변은 7일로 상이하다. 어느 값이 실제 정책 정답인지는 이 비교 실험이 검증하지 않는다.

### 해석 및 주요 제한

- 학습 데이터는 8개 예제로 작고, 평가 사례는 학습 예제와 의미상 매우 유사하거나 거의 같은 요청을 포함한다. 따라서 3/3 결과는 독립 held-out 검증이 아니며 일반화 또는 객관적인 성능 향상의 근거로 사용하지 않는다.
- 스크립트는 `category` exact-match를 기준으로 한다. JSON/분류 점검 3/3은 이 좁은 코드 기준이다. 답변의 사실 정확성, 정책 근거, 안전성, 일관성은 전반적으로 평가하지 않았다.
- 실행 중 `Sliding Window Attention is enabled but not implemented for sdpa` 경고가 출력됐다. Transformers도 pad token과 eos token이 같아 attention mask를 추론할 수 없다는 경고를 출력했다. 베이스 결과가 이 설정에서 영향을 받았을 가능성을 배제할 수 없으므로, 베이스 0/3 대 어댑터 3/3을 공정하고 정량적인 비교로 해석하지 않는다.
- `do_sample=False` 상태에서 저장된 generation config의 temperature/top_p/top_k 값이 무시된다는 경고도 나왔다. 이는 경고 자체가 곧 실패를 뜻하지는 않지만, 비교 재현성 점검 시 생성 설정을 명시적으로 정리할 수 있다.
- 어댑터 추론이 성공해 저장된 어댑터를 로드·사용할 수 있음을 확인했다. 다만 정확한 학습 로그, 실제 step/loss 및 학습 중 자원 사용량은 기록으로 확인되지 않았다.

## 3. 5단계 성능 측정 요약

동시성 1·2·4에서 각 4회, 요청 상한 128 tokens로 측정했다. 모두 성공했다. Aggregate 출력 처리량은 각각 **26.159, 50.734, 50.557 tokens/s**였다. 동시성별 표본이 작고 TTFT/장시간 안정성을 측정하지 않았으며, 전체 해석은 `docs/progress_report_v4.md` 참고. 서버 종료 후 MIG 사용량 16 MiB/40448 MiB, GPU 프로세스 없음이 확인됐다(v5).

## 4. 6단계 VL 정성 평가 요약

`datasets/images/val/drp.en_ko.in_house.selectstar_000307.jpg`를 `Qwen2.5-VL-7B-Instruct`로 처리했다. JSON 파싱은 성공했고, 모델 출력 품목 금액 합계(18,000+5,000원)는 출력 total 23,000원과 산술적으로 일치했다. 최대 GPU 메모리 할당은 15.80 GiB였다.

`datasets/jsons/val.json`에는 해당 이미지의 81개 word record, points/orientation/language, 이미지 크기만 확인됐고 전사 문자열이나 영수증 필드 정답은 없었다. 그러므로 이 정성 점검은 형식 및 내부 산술 일관성에 한정된다. 상호·날짜·총액·품목이 이미지와 정확히 맞는지는 검증되지 않았다. 세부 내용은 v6~v8 참고.

## 5. 종합 결론 및 종료 상태

- 계획된 기본 추론, vLLM API, RAG, QLoRA 어댑터 평가, API 성능 측정, VL 단일 이미지 데모를 실행했다.
- 이 실습은 파이프라인을 작동시키고 제약을 확인하는 학습용 데모로 마무리한다.
- 모델 성능 향상, 실제 출장 규정 답변 정확성, 영수증 정보 추출 정확성, 실서비스 배포 준비가 검증된 것은 아니다.
- 중요한 수치와 정책 답변은 원문과 사람이 대조해야 한다. 운영 배포 전에는 독립적인 holdout 데이터, 명확한 정답 레이블, 평가 지표, attention/generation 경고 점검이 필요하다.
- 사용자 공유 로그에서 5단계 서버 종료와 GPU 반환이 확인됐으며, 이후 VL·QLoRA 평가 실행 이후의 최신 GPU 상태는 별도로 보고되지 않았다. 새로운 GPU 실험 전에 `nvidia-smi`로 작업 상태를 재확인한다.
