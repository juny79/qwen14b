# 사내 AI 업무지원·생성형 미디어 도구 통합 개발안 v1

## 목적과 범위

기존 `application_development_plan_v1.md`의 문서 RAG MVP를 유지하면서, 다음 두 웹앱을 별도 제품 모듈로 개발한다.

1. **사내 AI 업무지원 웹앱**: 사내 승인 문서 검색·근거형 질의응답을 먼저 제공하고, 업무 요청 요약·분류는 별도 품질 검증 후 추가한다.
2. **이미지·동영상 생성/수정 웹앱**: Hugging Face의 오픈 가중치 모델을 서버에서 실행해 이미지 생성·인페인팅·변환, 텍스트/이미지 기반 짧은 동영상 생성 및 제한적 편집을 제공한다.

두 앱은 GPU를 공유할 수 있으나 모델 실행을 무제한 병렬화하지 않는다. A100 MIG 40GB는 필수 전제가 아니라 사용할 수 있는 자원 상한으로 취급한다. 실제 사용자 수요·동시성·응답시간을 측정해 모델과 자원을 조정한다.

## 제품 A — 사내 AI 업무지원

### MVP 사용자 기능

- 사내 인증 연동 지점(개발 단계는 로컬 테스트 인증; 운영 SSO 연동 필수).
- 승인 문서 업로드/목록/비활성화, 문서 owner·버전·유효일·그룹 권한 메타데이터 관리.
- TXT/Markdown 우선 ingestion, 청킹·CPU 임베딩·FAISS 인덱스 생성 및 검증.
- 문서 ACL을 검색 단계에서 적용하고, 답변에 문서명·버전·페이지 또는 청크를 인용.
- 근거가 없거나 ACL 필터링 뒤 결과가 없으면 답변을 보류.
- 사용자 피드백, request ID, 모델·인덱스 버전 표시.
- 이후 단계에서 업무요청 카테고리·우선순위·요약을 JSON 초안으로 생성. 승인 없는 외부 티켓/결재 자동 실행은 하지 않는다.

### 사용자 효용

문서 탐색 시간을 줄이고, 답변 출처를 직접 확인하며, 권한이 없는 문서가 결과에 포함되는 위험을 낮춘다. 요청 분류 기능은 검증 완료 후 담당자의 반복적인 triage를 보조한다.

## 제품 B — 이미지·동영상 생성 및 수정

### MVP 사용자 기능

- 프롬프트 기반 이미지 생성.
- 이미지 업로드 후 프롬프트 기반 수정(인페인팅/이미지 변환). 원본과 결과를 나란히 비교.
- 텍스트→짧은 동영상 및 이미지→짧은 동영상 작업을 비동기 작업으로 제출·취소·상태 조회·다운로드.
- 제한된 비디오 편집: 짧은 클립을 프레임으로 변환해 선택 구간/프레임에 적용한 뒤 영상으로 재조립하는 실험 기능. 프레임 단위 생성은 프레임 간 깜박임·인물/물체 일관성 저하가 있을 수 있음을 UI에서 고지한다.
- 출력에 사용 모델·revision·설정·seed 기록, 사용자 소유 작업만 조회/다운로드.
- 입력 형식·파일 크기·픽셀·영상 길이·프레임 수·출력 크기에 제한을 적용하고 임시 업로드/결과의 보존 및 삭제 정책을 둔다.

### 우선 추천 모델 3종과 라이선스 gate

A100 MIG `3g.40gb`에 한 번에 하나의 GPU 작업만 올리는 조건으로 아래 3종을 우선 벤치마크한다. 모델 카드와 라이선스는 배포 시점에 다시 확인하고, 정확한 commit revision을 고정한다.

| 용도 | Hugging Face 모델 ID | 추천 이유 | 40GB MIG 운용 판단 | 라이선스/제약 |
|---|---|---|---|---|
| 텍스트→이미지 생성 | `black-forest-labs/FLUX.1-schnell` | 12B급, 1~4 step 생성 지향, Diffusers 공식 pipeline 제공. 빠른 시안 생성용으로 적합 | BF16 상주 로딩 여유는 제한적일 수 있어 CPU offload부터 시작. 해상도와 동시 생성은 낮게 설정하고 peak VRAM/속도 측정 | Apache-2.0. 상업 사용 가능 라이선스지만 사용 정책·입력 권리 확인은 별도 |
| 마스크 기반 이미지 수정 | `diffusers/stable-diffusion-xl-1.0-inpainting-0.1` | 성숙한 Diffusers inpainting pipeline으로 지정 영역 추가·삭제·교체 MVP에 단순하고 예측 가능한 선택 | SDXL 계열이라 40GB 안에서 비교적 여유 있게 운용 가능. 우선 1024px, batch 1부터 시작 | CreativeML Open RAIL++-M. Apache와 동일한 무제한 라이선스가 아니므로 사용 제한과 조직의 상업 이용 조건을 검토 |
| 텍스트/이미지→동영상 생성 | `Wan-AI/Wan2.2-TI2V-5B` | 한 모델이 T2V와 I2V를 지원하며 모델 카드가 720p/24fps 및 단일 GPU 운용 절차를 제공 | 공식 예시의 24GB급 GPU 운용은 CPU/T5 offload 및 dtype 변환 설정을 사용한다. 40GB MIG에서 가능성이 높지만 생성은 무겁고 느릴 수 있으므로 짧은 길이·낮은 픽셀 수로 실측 | Apache-2.0. 생성 결과 사용 책임 및 안전 정책은 사용자/운영자가 부담 |

이 조합은 **이미지 생성 + 마스크 기반 편집 + 짧은 T2V/I2V**의 첫 파일럿 범위를 충족한다. SDXL inpainting은 Qwen-Image-Edit 같은 의미 기반 편집 모델과 동일한 기능이 아니다. 자연어로 이미지 전체를 바꾸면서 인물/제품 정체성을 유지하거나 글자를 정교하게 고치는 요구가 중요하면 `Qwen/Qwen-Image-Edit-2509`를 별도 후보로 평가할 수 있으나, 약 20B급으로 40GB에 BF16 상주시키기 어렵다. 양자화/CPU offload와 품질·속도를 별도 검증하기 전 기본 모델로 채택하지 않는다.

`Wan2.2-TI2V-5B`는 일반 동영상 편집이나 기존 클립의 정확한 프레임 유지형 video-to-video 편집 모델이 아니다. 우선 텍스트 또는 참조 이미지에서 새 짧은 영상을 만드는 기능으로 한정한다. 기존 영상의 객체 제거·교체·시간축 일관성 편집은 별도 모델·후처리 과제로 분리한다.

HF 모델 가중치는 애플리케이션 코드와 별도로 캐시/아티팩트 저장소에 관리한다. 자동으로 임의 모델을 내려받거나 미승인 라이선스 모델을 실행하지 않는다. 모델 ID는 설정 가능하되 승인된 allowlist 밖의 모델은 거부한다.

**출처(모델 카드):** [FLUX.1-schnell](https://huggingface.co/black-forest-labs/FLUX.1-schnell), [SDXL Inpainting 0.1](https://huggingface.co/diffusers/stable-diffusion-xl-1.0-inpainting-0.1), [Wan2.2-TI2V-5B](https://huggingface.co/Wan-AI/Wan2.2-TI2V-5B), [Qwen-Image-Edit-2509](https://huggingface.co/Qwen/Qwen-Image-Edit-2509).

운영 전 각 모델을 실제 MIG 할당에서 단독 실행해 peak VRAM, cold/warm start, 첫 결과 및 반복 생성 시간, OOM/실패율을 기록한다. 40GB 표시는 모델 실행에 전부 쓸 수 있는 VRAM을 뜻하지 않으며 vLLM이 GPU를 점유하는 동안 미디어 추론을 병렬 실행하지 않는다.

모델 라이선스와 사용 제한은 기술적 가중치 접근 권한과 별개로 조직의 법무/보안 담당자가 확인한다.

**권고 순서:** SDXL Inpainting으로 가장 간단한 이미지 편집 MVP를 검증하고, FLUX.1-schnell로 품질/생성시간을 평가한 다음, Wan2.2는 GPU 작업 창을 분리한 짧은 영상 파일럿으로 진행한다.

### 사용자 효용 및 한계

마케팅 시안, 콘셉트 이미지, 짧은 스토리보드/클립 제작의 초안 시간을 줄이고, 반복 수정 결과를 비교할 수 있다. 결과는 생성형 초안이며 사실성·저작권·초상권·브랜드 권리·상업 이용 가능성을 보장하지 않는다. 최종 게시 전 사람이 검수한다.

## 공통 아키텍처 원칙

- 웹/API는 인증·인가, 업로드 검사, 입력/출력 제한, request ID, 작업 상태, 오류 처리를 담당한다.
- GPU 작업은 중앙 job queue/lease로 직렬화 또는 승인된 동시성 제한을 적용한다. RAG LLM 추론과 이미지/비디오 생성이 MIG 자원을 초과해 경합하지 않도록 한다.
- GPU worker는 모델을 작업별로 매번 불필요하게 중복 로드하지 않도록, resident model 또는 명시적 모델 전환 정책을 갖는다. 초기 파일럿은 한 번에 한 GPU heavy job을 기본값으로 둔다.
- 인덱스, 업로드, 산출물, 모델 캐시, 인증정보를 서로 분리한다. 비밀정보는 환경변수/secret store에서 읽고 저장소·브라우저·로그에 기록하지 않는다.
- 원문 문서, 프롬프트, 개인 이미지/영상은 기본 로그와 메트릭에 남기지 않는다. 저장 기간·삭제·접근 감사 정책을 확정한다.
- 모델/입력의 라이선스, 개인정보 처리 근거, 사내 보안 기준은 운영 전에 책임자가 승인한다.

## 단계별 출시

### 0단계 — 정책·환경 결정

대상 사용자, SSO, 저장소, 허용 문서, ACL, 개인정보 등급/보존, 미디어 허용 목적, 모델 라이선스, 파일 제한을 확정한다. GPU/MIG 구성과 실제 사용 가능 VRAM을 다시 측정한다.

### 1단계 — 업무지원 RAG 웹앱 MVP

다중 문서 등록, ACL, 근거 인용/답변 보류, 피드백, 인덱스 rollback, 접근성 있는 기본 UI를 구현한다. 합성/비민감 데이터로 개발하고 권한 누출 테스트를 수행한다.

### 2단계 — 이미지 생성·수정

승인된 단일 이미지 모델부터 시작한다. 입력 검증, 비동기 작업, 결과 비교·다운로드, 사용자별 접근통제, 삭제 처리를 검증한다.

### 3단계 — 짧은 동영상 생성/수정 파일럿

경량 모델 한 종과 짧은 최대 길이·낮은 해상도부터 평가한다. 프레임/클립 품질, flicker, 작업시간, VRAM, 실패율을 측정한다. 프레임 기반 편집은 실험 기능으로 표기한다.

### 4단계 — 품질·보안·운영 검증 및 제한 파일럿

RAG의 retrieval/citation/abstention 및 ACL 누출 0건, 미디어의 안정성·정책·삭제·라이선스를 평가한다. 사용량 quota, 큐 포화 처리, GPU/RAM/disk 모니터링, 백업·복구 및 장애 대응을 검증한 뒤 승인 사용자에게만 공개한다.

## 필수 출시 제한

- 업무지원 응답은 초안이며, 결재·지급·계정/권한 변경 등 중대한 외부 작업은 사람 승인 없이 수행하지 않는다.
- 생성 이미지/영상은 사실 자료로 간주하지 않는다. 사칭·비동의 초상·불법/유해 목적을 방지하는 정책과 신고/삭제 절차를 둔다.
- 승인 전에는 인터넷 공개·실사용자 민감 문서/영상 업로드를 금지한다.
- 작은 데모 평가를 정확도·SLA 보증으로 표현하지 않는다.
- GPU는 고스펙이라는 이유로 동시 작업량을 임의로 늘리지 않고, 실제 부하 시험으로 capacity를 결정한다.
