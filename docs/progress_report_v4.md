# Qwen2.5 A100 MIG 실습 진행 보고서 v4

- **보고서 버전:** v4 (v1~v3 보존, 새 진행 결과 추가)
- **기준 시점:** 2026-10-09, 사용자가 공유한 서버·API·벤치마크 실행 로그 기준
- **프로젝트:** G-NAHPM-40 A100 MIG 40GB 오픈소스 AI 실습
- **현재 진행:** 0~3단계 완료(v2 기록), 4단계 어댑터 산출물 확인·평가 미확인(v3 기록), 5단계 API 성능 측정 실행 완료. 6단계 VL은 미실행.
- **검증 범위:** 5단계 수치는 사용자가 공유한 터미널 출력에서 옮겼다. 결과 CSV는 사용자의 인스턴스에 생성된 것으로 보고되었으며, 본 작업 공간에서 파일 내용을 직접 확인하지는 않았다.

> 이전 버전 보고서는 스냅샷으로 보존한다. 후속 실행 결과는 본 파일을 덮어쓰지 않고 v5 등 새 문서로 기록한다.

## 2. 5단계 실행 환경 및 사전 확인

- GPU: NVIDIA A100 80GB PCIe, MIG 활성화. 서버 시작 직전 `nvidia-smi`에서 MIG 장치 메모리 40448 MiB 중 16 MiB 사용으로 표시됐고 실행 중 GPU 프로세스는 없었다.
- API 서버: vLLM 0.7.3, 모델 `Qwen/Qwen2.5-14B-Instruct`, served name `qwen14b`.
- 서버 설정: BF16, `max_model_len=4096`, `max_num_seqs=2`, `gpu_memory_utilization=0.90`, `127.0.0.1:8000` 바인딩.
- vLLM 로그: 모델 가중치 27.5681 GB 로드, MIG 기준 총 GPU 메모리 39.50 GiB 중 vLLM 사용 예산 35.55 GiB, KV cache 7.45 GiB로 기록. `Application startup complete` 확인.
- API 테스트: `/v1/models`에서 `qwen14b` 확인, 한국어 chat completion 성공. 사용량 71 tokens (prompt 49, completion 22).
- 서버는 기본 실습 API 키를 사용했다. 서버 스크립트 경고대로 localhost/SSH 터널 실습 범위에서만 사용해야 한다.

## 3. 벤치마크 결과

실행 명령은 동시성 1·2·4, 각 수준당 4회 요청, 요청당 최대 128 tokens였다. 워밍업 요청 1회는 통계에서 제외됐다. 아래 측정은 비스트리밍 완료 응답 기준이다.

| 동시성 | 요청 성공/전체 | 평균 지연 (초) | 중앙값 (초) | p95 (초) | 최대 지연 (초) | 출력 토큰 합계 | Aggregate 출력 처리량 (tokens/s) |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 1 | 4/4 | 12.196 | 12.195 | 19.527 | 19.527 | 512 | 26.159 |
| 2 | 4/4 | 7.513 | 7.513 | 10.024 | 10.024 | 512 | 50.734 |
| 4 | 4/4 | 7.560 | 7.560 | 10.067 | 10.067 | 512 | 50.557 |

- 모든 측정 요청에서 실패는 0건이었다. 4개 요청의 출력 토큰 합계가 매 수준 512이며 요청별 최대 생성량이 128이므로, 모든 요청이 128-token 상한에 도달한 결과다. 따라서 이번 결과는 해당 길이 상한에서의 측정이며 자연 종료까지의 평균 응답 길이나 사용자 체감 품질을 비교한 것은 아니다.
- 동시성 1에서 2로 올릴 때 aggregate 처리량이 약 26.2에서 50.7 tokens/s로 상승했다. 동시성 2와 4에서는 각각 약 50.7, 50.6 tokens/s로 거의 차이가 없었다.
- 서버 설정상 `max_num_seqs=2`이므로, 동시성 4 요청은 서버에서 최대 2개씩 처리되고 나머지는 대기할 수 있다. 이번 결과의 처리량 정체와 일치하는 가능한 설명이지만, 네 번씩의 짧은 측정만으로 병목 원인을 확정하지 않는다.
- 각 수준의 요청 수가 4개뿐이며 스크립트의 p95는 이 작은 표본의 경험적 값(사실상 최댓값에 가까움)이다. 통계적 성능 보증으로 해석하면 안 된다.
- 벤치마크는 TTFT(첫 토큰 지연), 스트리밍 체감 지연, 장시간 안정성, 반복 실행 간 변동을 측정하지 않았다.

## 5. 다음 단계

1. API 테스트 및 성능 측정이 끝났으므로, **터미널 A에서 vLLM 서버를 정상 종료**한다. 서버가 실행된 터미널에서 종료를 요청하고 프로세스가 내려간 뒤 확인한다.
2. `nvidia-smi`로 MIG 메모리가 반환됐는지 확인한다. 권한 문제로 메모리 수치가 보이지 않으면 적어도 본인 서버 프로세스 종료 여부를 확인한다.
3. 다음 실습으로 넘어가기 전 GPU에 다른 작업이 없는지 확인한다. 본인 프로세스가 아닌 작업을 임의로 종료하지 않는다.
4. 다음 단계(6단계 VL)는 개인정보가 없는 샘플 이미지를 사용하고, 다른 GPU 작업 종료 후 실행한다.

현재 서버가 계속 실행 중인지 여부는 공유된 벤치마크 출력만으로 확인되지 않는다. GPU 자원을 반환하기 전까지는 추가 GPU 실험을 동시에 시작하지 않는다.
